# Index performance report

PostgreSQL 16, 556,800 rows in `student_question_mark`, offering 200. Median over 3 alternating rounds (5 runs each; programme run: 1 per round). Generated by `python -m scripts.explain_report`.

| Operation | Without 006 indexes (ms) | With indexes (ms) | Speed-up |
| --- | ---: | ---: | ---: |
| Scores for one CO across all offerings (root-cause path) | 185.0 | 83.3 | 2.2x |
| CO aggregation, one offering | 22.3 | 21.9 | 1.0x |
| sp_compute_attainment, one offering | 55.6 | 49.0 | 1.1x |
| sp_compute_all, whole programme | 13,608.7 | 13,740.8 | 1.0x |

The per-offering computation reads marks through constraint indexes that exist either way (`enrollment` UNIQUE `(offering_id, usn)` and the `student_question_mark` primary key), so its plan is the same with or without 006. The 006 indexes serve access by CO across offerings — root-cause analysis and trends — which otherwise scans every mark.
